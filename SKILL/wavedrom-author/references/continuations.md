# 核心规则：状态持续，不等于逐拍重复字符

AI 先在 LWF 原稿中逐拍写值并检查。以下表格描述**转换器**如何输出状态变化事件；不要由 AI 手工拼接或修改生成后的 wave。

| 用户含义 | 默认 wave | 不应默认生成 |
|---|---|---|
| 高电平持续五拍 | `1....` | `11111` |
| 低电平持续五拍 | `0....` | `00000` |
| 两拍低、三拍高、两拍低 | `0.1..0.` | `0011100` |
| 高电平第一拍任务 A、第二拍任务 B，明确要求分开 | `11`，并添加任务标注 | 未经确认合并成 `1.` |
| 一个总线数据 A 保持三拍 | `=..`，data 为 `["A"]` | `===`，data 为 `["A","A","A"]` |
| 连续两次独立交易，数值恰好都为 A | `==`，data 为 `["A","A"]` | 按值相同合并成 `=.` |
| 时钟连续运行五拍 | `p....` | 将 `.` 理解为时钟停住 |

## 编码步骤

1. 先列逻辑状态或数据的**区间**，而不是直接拼接字符串。
2. 区间第一拍写状态字符，剩余拍写 `.`。
3. 实际状态变化、数据框的独立交易、用户指定的任务边界必须开新区间。
4. 用户明确强调相邻同电平拍时，可重复写 `1`/`0`；用 `head`、`node`、`edge` 或正文解释这些拍分别是什么。不要声称 `11` 是平滑高电平：官方会画出分界尖刺。
5. 不确定“连续两拍有效”是持续状态还是两次独立事务时，控制线默认持续；总线事务若会影响数据标签数量，应结合协议上下文判断，必要时仅询问这项歧义。
6. 生成后检查每段 `00` / `11` / `hh` 等重复：逐段给出保留理由；没有理由就用延续符重写，再校验。

不要全局对字符串做替换：它可能误合并任务边界、等值但独立的总线交易，或改变带节点/子周期的图。
