# LWF v1：Language-oriented Waveform Format

**语言化波形格式**，面向 LLM 的逐拍原稿。文件扩展名 `.lwf`；它不是 VCD/UML 标准，也不是 WaveDrom 原生语法。

## 最小语法

```text
@信号a, type=bin
0
1
1
0

@信号b, type=bus
2
z
5
"INIT"
```

- `@名称, type=bin` 或 `@名称, type=bus` 开始信号；名称不可重复。头部也接受中文逗号 `，` 和全角等号 `＝`。
- 每个非空数据行**恰好一拍**；空行、整行 `#` 注释不计拍。第一个值为第 0 拍。所有信号从同一第 0 拍开始。
- `bin` 仅接受 `0`、`1`、`x`、`z`，不接受 `.`、`p` 等压缩/时钟指令。需要时钟时也逐拍列值；在说明中约定一拍是否为半周期。
- `bus` 接受十进制整数、十六进制/二进制整数字面量或双引号字符串。它们是显示标签，不推断位宽、符号或数值换算。只有显示标签相同才合并，`0x02` 与 `2` 保持不同。
- 不加引号的 `x/z` 表示未知/高阻；`"x"`、`"z"` 是普通数据。英文双引号字符串按 JSON 转义规则解析；外层中文双引号也接受。推荐 AI 始终输出英文双引号。
- 行末 `!` 表示强制新段，例 `1 !`、`"A" !`。字符串里的感叹号如 `"DONE!"` 只是标签。`!` 不增加拍数；第一拍加 `!` 不产生额外效果。
- 默认必须等长，长度不一致就停止转换，不补值。明确要求不同长度时可加 `--allow-unequal`，仍只保留原始长度，不自动延续、截断或补齐。
- 不支持行内注释、总线宽度声明、节点、箭头、phase、period、半拍标记等高级扩展。需要这些功能时先说明 v1 边界，不绕过原稿直接修补生成文件。

## 从原稿检查，而不是从压缩结果猜测

先运行：

```bash
node scripts/compile.cjs diagram.lwf --check
```

它会显示每条信号的拍数以及 `0:值 1:值 ...` 检查表，错误带源文件行号；`!` 保留在表中，方便逐拍审阅。该命令不生成 WaveJSON。

**AI 必须进一步检查语义**：复位、有效电平、每个采样时刻、握手、背压数据稳定、任务边界和观察窗口是否满足需求。语法检查成功不是协议验证成功，也不是仿真通过。

确定原稿正确后再转换：

```bash
node scripts/compile.cjs diagram.lwf --out diagram.generated.json
```

转换规则：首拍或值变化写状态；同值后续拍写 `.`；`!` 强制写新状态/总线框。总线只有产生新数据框时才追加 data 标签。`1 1 1 1 1` 自动变为 `1....`，AI 不需要自行压缩。

默认拒绝覆盖已有文件，防止误覆盖原稿或用户作品。迭代时使用新的产物名或新的输出目录；不要删除用户文件以绕过此保护。省略 `--out` 会把纯 JSON 输出到 stdout；错误/告警写 stderr。

## 唯一原稿与迭代约定

- `diagram.lwf` 是人工和 AI 共同维护的唯一原稿。
- `diagram.generated.json`、SVG/PNG 都是可再生成的产物，**禁止把它们当作修改入口**。
- 用户说“第 4 拍改成 1”，先定位 LWF 对应信号的第 4 个零基拍号，再修改原稿、检查、重新生成。不要把文件行号当成拍号，信号头/注释/空行都不计拍。
- 交付变更摘要：信号名、拍号、旧值→新值、是否新增/移除 `!`。随后附原稿和生成物。
- 收到旧 WaveJSON 而没有 LWF 时，先重建逐拍原稿并核对等价性，再迭代；不能丢掉用户原有的有意边界。无法用 v1 表达的部分须先说明或请求原稿，不能静默降级。
- 要区分任务 A/B 或相同数值的独立交易时，在第二项的第一拍加 `!`，用整行注释说明理由。不要为了“画得平滑”自动删除这些标记。
