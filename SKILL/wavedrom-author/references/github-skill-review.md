## 建议优先级

1. **协议细分的 LWF 练习题与时序依据**：APB 最适合作为下一批，分别覆盖 Setup/Access、等待、连续、错误；再做 AHB/SPI。保留“先按描述写 LWF、后对答案”的训练方式。
2. **明确的逐图命题与逐周期事件表**：例如“背压期间 DATA 不变”“最后一拍才有 WLAST”，给出格号和边沿前后值。不是把整个协议笼统标 PASS。
3. **信号来源与证据表**：RTL 文件/行号、输入/输出/内部、时钟域；图片来源则记录行位置、区间、标签、未确定项。不要把图片推测写成源码事实。
4. **更细的视觉回查清单**：渲染图实际像素、未要求的同电平尖刺、多余数据框、标签截断、首末窗口、断口一致性。我们已有渲染检查原则，可把这些落为固定检查项。
5. **修改前后对照和事件差异**：除 LWF 格值变更外，列出握手/响应/延迟事件变化，并给双图。
6. **语义分组、阶段颜色、离线说明页**：适合复杂总线；需先设计 LWF 元数据/展示层支持，不能为加颜色、分组或箭头直接补丁派生 JSON。
7. **结构图与时序联动**：ICG/分频/CDC 的结构与波形放在同一交付页；属于后续扩展，不是当前恢复图片的前置要求。

## 不直接采用的规则

- Auyuir 的速查表把 x 写成高阻/无效、将 P/N 的含义写为负极性；本项目继续使用 x=未知、z=高阻，P/N 为带边沿标记的时钟字符，不复制这些表述。其总线标签计数只强调 2–9，本项目继续覆盖 = 及 2–9。
- 不能把“非阻塞赋值下一周期才变”作为无条件规则。必须区分上升沿前采样和该沿后更新，以及表中周期编号的定义。
- arthurwanggit 的统一 phase 约定只适用于它的示例，不能取代本项目的时钟域与边沿检查；相位方向和视觉采样关系需要在实际渲染中核实。
- 外部“保持双线空标签而不是 x”的展示习惯不能覆盖图片真实的未知/高阻语义；也不能自动删除用户有意保留的重复边界。
- 客户端专属的固定输出目录、禁止箭头等偏好不应变成本项目通用限制。外部代码/文字如要复制，还需按实际许可证保留要求；本轮只整理思路，没有引入外部实现。

## 对图片恢复的结论

读到的这些说明对“直接生成、渲染、检查”较完整，但没有提供我们要求的整套流程：先定位时钟 → 建立统一细时间格 → 每格列出全部信号值 → 核对持续区间/信号关系 → 转置成 LWF → 门禁后编译。保留这个阶段，并把外部的协议案例、证据记录和视觉检查接到它前后更合适。
