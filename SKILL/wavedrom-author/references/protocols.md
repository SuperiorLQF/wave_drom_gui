# 协议与时间对齐

这些是编图约束，不是任何芯片的完整协议规格。

## Ready/valid

- 只有采样边沿的 `valid && ready` 为 1 才发生传输，不能仅看 valid 上升沿。
- backpressure 期间，如所用协议要求，valid 与 data 必须稳定；例子中采用这个规则。
- `examples/ready-valid.json`：基准周期为 1，时钟 phase=0.5，在半整数位置上升；以下数值在采样前已经稳定。valid 在区间 [2,6) 为 1，ready 在 [4,8) 为 1。
- t=3.5：valid=1、ready=0，A 等待；t=4.5：传输 A；t=5.5：传输 B；t=6.5 时 valid 已低，不传输。驱动在整数拍边界、采样在半整数时刻，避免把同一时刻的新值误当作采样前值；真实设计仍需核对驱动与采样区。
- 总线 A 位于 [2,5)，B 位于 [5,6)，同时应说明数据在采样前已稳定；示意图不表达建立/保持时间的绝对数值。

## 请求/应答

`examples/request-ack.json`：req 在 [2,7)，ack 在 [5,7)。a 标记 req 的第 2 拍、b 标记 ack 的第 5 拍；箭头仅标记 3 个基准周期的间隔，不表示额外硬件通路。实际协议是否允许 req 在 ack 前撤销，需要单独确认。

## 同电平毛刺

`examples/intentional-glitches.json` 将 `1111` 与 `1...`、`0000` 与 `0...` 放在一起。前者的尖刺来自 WaveDrom 状态砖块，不证明硬件发生了真实窄脉冲。不得把图形符号当作经过仿真测得的模拟毛刺。

## SPI / I²C / DDR 等协议

1. 先确认模式与参考时钟、边沿、位序、字长、片选/复位、三态规则；不要靠信号名推断 CPOL/CPHA 或 DDR 采样方式。
2. 按半周期列出数据驱动与采样时刻，再转换到整数网格或经验证的 period/phase。明确示意时间单位。
3. I²C 的高电平与总线释放不等同：开漏驱动释放可写为 z，但总线上实际读到的高电平还依赖上拉；应区分驱动信号与总线信号。
4. 不清楚具体器件的延迟与建立/保持时间时，不填写貌似精确的 ns 值。
