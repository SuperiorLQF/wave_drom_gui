# 自学与更新检查

## 首次使用 / 内容更新

1. 阅读 `examples/catalog.json` 和 `examples/lessons/` 下全部任务；此时不要读答案。逐个根据任务独立写 LWF，保存工作稿。原生扩展任务写可表达的 LWF 和不支持字段的说明。
2. 再打开对应参考 `.lwf` 和 `.json`，以及 `examples/README.md`。必须熟悉目录中所有样例，不能只看当前要画的协议。用 `study.cjs compare <id> <attempt.lwf>` 比对可逐值比较的任务。
3. 对每个差异解释：边沿识别、时钟域、更新/采样、x/z 或 ! 的哪一项理解有误。修正练习，重新执行 skill 的同步与信号关系门禁，再转换练习为 JSON 并与参考对照。目录标为 syntax 的无时钟题仅检查语法及题目语义，同步项明确记为“不适用：纯语法练习”，不得虚报同步 PASS；native-reference 则完成解释任务，不强行生成 v1 不支持的字段。不能只运行结构脚本就宣称学会。
4. 在自己的工作目录保存学习记录：样例目录版本/内容摘要、每题首次尝试文件、差异、修正、最终门禁结果，以及原生扩展能力边界。失败或不明白的案例标 FAIL/UNKNOWN；全部完成后才开始正式任务。不要求用户人工确认通过。
5. 后续会话若没有可读取的完成记录，按初次使用处理。有记录则对比 `prepare` 生成的快照；样例、规则或转换器更新后重新学习，不能沿用旧 PASS。

这种学习是 AI 在当前工作上下文中阅读、练习和保存记录，不修改模型权重，也不保证跨会话自动记忆。

## 定时后台检查

仓库的 `.github/workflows/wavedrom-study.yml` 以北京时间（Asia/Shanghai）每日 04:00 为默认，使用 UTC `0 20 * * *`。GitHub schedule 有排队延迟，不保证准点；workflow 必须进入默认分支且 Actions 启用才会运行。也支持手动触发。

它检出默认分支最新版本，用缓存中的上次检查快照比对 `examples/`、规则和脚本的 SHA-256；首次运行/缓存丢失会重新列出全部任务。发现任何变更后要求重学全部样例，并运行参考配对及针对性时序断言。检查无变更时清单明确显示无更新。

结果在 Actions Summary 和 `wavedrom-study` artifact 中。任务仅有只读仓库权限，不推送代码、不发布、不调用模型；自动检查完成不代表 AI 已完成语义学习。若宿主支持真正的定时 AI 会话，可将下列提示作为每天 04:00 的任务内容；没有此能力时，AI 在下次使用 skill 时消费清单，不能宣称已自主后台学习。

```text
读取 wavedrom-author SKILL.md 和最新 examples/catalog.json，检查样例与规则是否更新。
不要仅依赖昨天的结论。按 self-study.md 对全部新版本案例先独立写 LWF，后读参考 LWF/JSON 对照。
记录首次尝试、差异、修正、同步和关系门禁；不支持的原生扩展要说明。
有 FAIL/UNKNOWN 则停止转换并记录原因。完成后保存学习记录和版本快照。
不改参考答案，不发布、提交或推送代码，不把练习称为模型训练或仿真验证。
```

本地也可检查（路径相对 skill 目录，状态和输出应放在自己的工作目录）：

```bash
node scripts/study.cjs prepare /path/to/state.json /path/to/study-report
```

该状态是“已检查”的快照，与 AI 自己的“已学会”记录分开。输出目录包含 `study-task.md` 和 `snapshot.json`。
